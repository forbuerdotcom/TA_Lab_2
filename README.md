## Описание

Программа относится к лабораторной работе №2 «Модули и пакеты Python. ООП» (Вариант №10 — «Отделочные материалы»).

Пользователь вводит площадь помещения и цену за единицу материала, выбирает тип материала из выпадающего списка и получает:

- необходимое количество материала с учётом технологического запаса;
- итоговую стоимость закупки.

Каждый расчёт автоматически сохраняется в базу данных SQLite, а результат можно выгрузить в отчёт формата Microsoft Word (.docx).

Проект реализован с упором на модульную структуру и объектно-ориентированное программирование: бизнес-логика вынесена в отдельный пакет, интерфейс отделён от расчётов, общий для всех материалов функционал собран в абстрактном базовом классе.

## Возможности

- Расчёт количества и стоимости для трёх типов материалов: обои, плитка, ламинат.
- Учёт технологического запаса: +10 % для обоев, +5 % для плитки и ламината.
- Валидация ввода: площадь должна быть больше 0, цена — неотрицательной.
- Сохранение истории расчётов в базу данных SQLite3.
- Экспорт результата расчёта в отчёт Word (.docx).
- Покрытие тестами (pytest), запуск в Docker.

## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone <ссылка на репозиторий>
cd TA_Lab_2
```

### 2. Создать виртуальное окружение

```bash
python -m venv .venv
```

Активация:

```bash
# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

### 4. Запустить программу

```bash
python main.py
```

Откроется окно приложения «Вариант №10. Отделочные материалы».

## Как пользоваться

1. Введите площадь помещения в квадратных метрах. Значение должно быть числом больше 0.
2. Выберите тип материала из выпадающего списка: «Обои», «Плитка» или «Ламинат».
3. Введите цену за одну единицу материала:
   - для обоев — цена за рулон (руб.);
   - для плитки и ламината — цена за квадратный метр (руб.).
   Цена не может быть отрицательной.
4. Нажмите кнопку «РАССЧИТАТЬ». В правой части окна появится количество материала с учётом запаса и итоговая стоимость. Расчёт автоматически сохранится в базу данных.
5. Нажмите кнопку «СОХРАНИТЬ ОТЧЁТ» и укажите путь к файлу — результат будет выгружен в документ Word (.docx).

При некорректном вводе (не число, отрицательная площадь или цена) программа покажет окно с описанием ошибки и не выполнит расчёт.

## Формулы расчёта

### Обои

Один рулон покрывает 5 кв.м. Рулонов можно купить только целое количество, поэтому результат округляется вверх:

```
количество рулонов = ceil(площадь × 1.1 / 5)
итоговая стоимость = количество рулонов × цена за рулон
```

Пример: площадь 50 кв.м, цена 1000 руб. → 50 × 1.1 / 5 = 11 рулонов → итого 11 000 руб.

### Плитка и ламинат

Материал измеряется в квадратных метрах, поэтому достаточно добавить запас 5 %:

```
количество = площадь × 1.05
итоговая стоимость = количество × цена за кв.м
```

Пример: площадь 10 кв.м, цена 500 руб. → 10 × 1.05 = 10.5 кв.м → итого 5 250 руб.

## Архитектура (ООП)

Все материалы наследуются от абстрактного базового класса `Entity`, который реализует общую логику и валидацию.

```
        Entity (ABC)
       /     |      \
WallPaper  Tile   Laminate
```

### Класс Entity (абстрактный базовый класс)

| Элемент | Тип | Описание |
|---|---|---|
| `area` | managed-атрибут (property) | площадь, проверяется: значение > 0 |
| `price` | managed-атрибут (property) | цена за единицу, проверяется: значение ≥ 0 |
| `calculate_quantity()` | abstract method | расчёт количества материала |
| `get_unit()` | abstract method | единица измерения результата |
| `get_price()` | method | итоговая стоимость = количество × цена |
| `__init__` | dunder | конструктор |
| `__str__` | dunder | человекочитаемое представление объекта |
| `__repr__` | dunder | представление для отладки |

Класс `Entity` объявлен через `ABC` и декоратор `@abstractmethod` — его нельзя инстанцировать напрямую, только через наследников.

### Наследники

| Класс | Запас | Единица измерения | Особенность расчёта |
|---|---|---|---|
| `WallPaper` | +10 % | рулоны | округление вверх до целого рулона (`math.ceil`) |
| `Tile` | +5 % | кв.м | без округления |
| `Laminate` | +5 % | кв.м | без округления |

Каждый наследник переопределяет абстрактные методы `calculate_quantity()` и `get_unit()`, а также имеет собственные `__str__` и `__repr__`.

## База данных

Используется SQLite3, файл базы — `calculations.db`, создаётся автоматически при первом запуске.

Схема таблицы `history`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER, PRIMARY KEY AUTOINCREMENT | номер записи |
| `material` | TEXT NOT NULL | тип материала |
| `area` | REAL NOT NULL | площадь помещения |
| `price` | REAL NOT NULL | цена за единицу |
| `quantity` | REAL NOT NULL | рассчитанное количество |
| `total_cost` | REAL NOT NULL | итоговая стоимость |

Модуль `database.py` предоставляет две функции:

- `init_db()` — создаёт таблицу, если её нет (выполняется при запуске программы);
- `save_calculation(...)` — сохраняет результат одного расчёта.

## Тестирование

Тесты покрывают: расчёт количества и стоимости для всех трёх материалов, округление рулонов вверх, единицы измерения, валидацию площади и цены (граничные значения), dunder-методы `__str__` / `__repr__`, наследование и запрет инстанцирования абстрактного класса, сохранение в базу данных, формирование отчёта Word.

Запуск:

```bash
pytest test_modules.py -v
```

Ожидаемый результат — все тесты проходят успешно (14 passed).

## Запуск в Docker

Сборка образа и запуск тестов внутри контейнера:

```bash
docker build -t ta_lab_2 .
docker run ta_lab_2
```

При сборке образа автоматически устанавливаются зависимости из `requirements.txt`; при запуске контейнера по умолчанию выполняются тесты pytest.

Примечание: графический интерфейс Tkinter требует доступа к дисплею, поэтому внутри контейнера запускается тестовое окружение. Для работы с GUI запускайте программу локально (`python main.py`).

## Возможные проблемы

**`ModuleNotFoundError: No module named 'docx'`** — не установлена библиотека python-docx или не активировано виртуальное окружение. Выполните `pip install -r requirements.txt` при активированном `.venv`.

**`ModuleNotFoundError: No module named 'tkinter'`** — в некоторых сборках Python под Linux tkinter установлен отдельно: `sudo apt install python3-tk`.

**Тесты не находятся pytest** — запускайте pytest из корневой папки проекта, где лежит `test_modules.py` и пакет `materials_package`.

**Файл `calculations.db` в репозитории** — база данных не входит в git (исключена через `.gitignore`); она создаётся автоматически при первом запуске программы.
